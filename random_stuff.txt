**On extension vs. app — here's the call, and the honest reasoning:**
Lovable generates standard React web apps, not packaged browser-extension bundles (manifest.json, background service workers, content scripts). So rather than asking Lovable to build something it structurally can't produce, the prompt below has it build a **web app** that achieves the same 5-second screenshot loop using the browser's built-in **Screen Capture API** (`getDisplayMedia`) — the user grants one-time screen-share permission in the browser tab, and the app captures a frame to canvas every 5 seconds and POSTs it. This is honestly the better MVP/demo choice anyway: it works in any modern browser with zero install friction, which is exactly what you want walking into a room with Microsoft employees. A true background browser extension is a legitimate v2/production path, but it's out of scope for what Lovable can output — worth saying that plainly if anyone asks "is this an extension?" in your demo.

## PROMPT FOR LOVABLE

I'm building **YTG (Your Truest Guardian)** — a gamified content-monitoring web app for parents/caregivers and individuals who want to proactively avoid harmful content online, with a reward system that reinforces good avoidance behavior instead of just blocking things outright.

### The problem and the philosophy

Exposure to hateful, extremist, and psychologically harmful content online — especially for young people — is a real driver of radicalization, poor mental health, and normalized hate. Most existing tools (parental control apps, content filters) work purely through restriction: block the site, log the violation, punish after the fact. That approach treats the symptom, not the behavior.

YTG is built on a different premise: **hate and harmful ideology take root through repeated, normalized exposure — so the fight against them starts with helping people build the habit of actively recognizing and walking away from that content, and reinforcing that choice positively.** Instead of only blocking, YTG watches, gently warns, and then *rewards* the person for choosing to disengage. The goal is to build a real behavioral habit of avoidance, not just a technical barrier that a determined person routes around.

This matters most for youth, who are both the most frequent targets of algorithmically-pushed extremist and harmful content, and the most able to build durable habits early. But the product also serves individual adults who want the same kind of support for their own browsing habits, without a guardian involved at all.

### The two audiences, and how the experience differs for each

**1. Caregiver / Parent (the "Guardian" account holder)**
This person sets up and configures monitoring for one or more dependents (or for a whole family). Their experience should feel calm, clear, and trustworthy — like a well-designed admin dashboard, not a toy. They need to:
- Create a Guardian (family or personal type)
- Connect dependents/offspring to that Guardian
- Configure what content categories to restrict (e.g. "extremist content," "graphic violence," "gambling" — a flexible list, not hardcoded)
- Set strictness level (weak / normal / harsh) — this controls how aggressively content gets flagged
- Customize the warning and applause messages shown to the person being monitored (so it can sound like *them*, not a generic system — e.g. "Please skip this one for me, okay?" instead of a cold system alert)
- Decide whether a points-loss penalty is enabled for repeated/ignored warnings, and how many points are at stake
- View a dashboard of recent flagged events/reports across all connected dependents
- Turn monitoring on/off for the household

**2. Youth / Individual (the monitored person)**
This person's experience should feel encouraging, game-like, and rewarding — never punitive-feeling by default, even though a penalty mechanic exists for guardians who opt into it. Think more "duolingo streak" energy than "your parents are watching you" energy, even though, functionally, they are. They need to:
- See their current point balance and recent activity clearly
- Get a warning overlay when something restricted is detected on their screen — this should feel like a caring nudge, not a scary lockout. Show the guardian's custom warning message here.
- See positive reinforcement (the custom "applause" message, a points animation, maybe a streak counter) when they successfully avoid content for the required duration
- Browse and redeem a rewards store (gift cards, and other reward types as configured)
- See their history/streaks in a way that feels motivating, not surveillance-heavy

### The core technical loop (this is the most important part to get right)

The monitoring works through a **repeating 5-second screen-capture loop**, running in the browser tab once the user has started a monitoring session:

1. On session start, request screen-share permission via the browser's Screen Capture API (`navigator.mediaDevices.getDisplayMedia`).
2. Every 5 seconds, capture the current frame to an off-screen `<canvas>`, convert it to a PNG blob.
3. POST that PNG blob as multipart form data to the backend's scan endpoint for the active session.
4. The backend responds with a JSON object describing whether the content was flagged, a description, whether a warning should be shown, and current session state (warning active, points awarded, etc.).
5. The frontend reacts to that response:
   - If flagged: show the warning overlay with the guardian's custom warning message.
   - If the warning clears (content no longer flagged after being flagged): show a subtle "still working" or countdown state while the backend's avoidance timer runs.
   - If points were awarded: show the applause message and a satisfying points-earned animation.
6. Repeat every 5 seconds for as long as the session is active. The user can stop the session manually at any time (this should always be an easy, visible, unhidden action — never make it hard to turn off monitoring of your own accord in the individual-account flow).

The backend and all API routes already exist — I'll wire those up manually. For now, build the frontend to call placeholder fetch functions against a configurable `API_BASE_URL`, structured cleanly so I can drop in the real endpoint paths afterward. Don't build authentication logic beyond calling a login/signup endpoint — assume the backend handles all of that.

### Screens/pages to build

- **Landing/marketing page** — brief, explains the product and philosophy in approachable language (not preachy), clear CTA to sign up as either a Guardian or an Individual.
- **Auth** — signup/login.
- **Onboarding wizard** — after signup: choose account type (Family Guardian vs. Personal/Individual), create the Guardian, and if Family, a step to connect a dependent account.
- **Guardian Settings page** — strictness selector, restriction category manager (add/remove tags), custom warning/applause message editors, points-loss toggle + configurable penalty amount, on/off toggle for monitoring.
- **Guardian Dashboard** — overview of connected dependents, their current status (monitoring active? recent flags?), and a feed of recent reports/alerts.
- **Monitoring Session view (youth/individual-facing)** — this is where the screen-capture loop runs. Shows current points balance, session status, and handles the warning overlay / applause states described above.
- **Rewards Store** — browsable list of rewards, current point balance, redeem flow.
- **Reports/Alerts inbox (Guardian-facing)** — list of flagged events with timestamps and descriptions, per dependent if Family type.

### Visual and UX direction

- **Guardian-facing screens**: clean, calm, professional — think a well-designed admin/analytics dashboard. Legible typography, clear data hierarchy, muted confident color palette. This person needs to trust the tool, not be delighted by it.
- **Youth/individual-facing screens**: warmer, more energetic, game-like — smooth animations on point gains, a visible streak/progress element, satisfying micro-interactions on redeeming rewards. This should feel closer to a wellness or habit-tracking app than a monitoring tool, without being childish — it needs to work for teenagers, not just young kids.
- Both experiences should share a coherent visual identity (same type system, same core palette family) so it's clearly one product, just tuned differently per audience.
- The warning overlay specifically needs care: it should interrupt without feeling punitive or alarming — no harsh red error-style treatment. Think a supportive nudge, not a security lockout screen.

### Explicitly out of scope for now

- **Do not build a mascot/character.** A future version of this product will include an animated companion character (similar in spirit to Duolingo's owl) that delivers warnings and celebrations. For now, skip this entirely — use clean text/UI states instead of any character or avatar. I'll integrate the character separately later once the interaction states are finalized.
- Don't build real backend logic — all API routes exist and I'll wire them up.
- Don't build a literal browser extension package — this is a web app using the Screen Capture API, as described above.

```bash
  -H "Content-Type: application/json" \
  -d '{
```

```bash
    "guardian_id": "GUARDIAN_ID_HERE"
  }'
```

### `GET /sessions/{session_id}`
Fetches a single session by ID — use this for cheap polling of current state (warning active? timer running?) without uploading a new screenshot.

```bash
curl http://localhost:8000/sessions/SESSION_ID_HERE
```

### `GET /sessions/guardian/{guardian_id}`
Lists all active sessions under a given Guardian (e.g. all currently-monitored dependents at once, for a parent dashboard).

```bash
curl http://localhost:8000/sessions/guardian/GUARDIAN_ID_HERE
```

### `DELETE /sessions/{session_id}`
Deletes/ends a session (e.g. on logout or after a period of inactivity).

```bash
curl -X DELETE http://localhost:8000/sessions/SESSION_ID_HERE
```

### `POST /sessions/{session_id}/scan` — core monitoring loop
Uploads a screenshot for classification. This is the endpoint the extension calls every 5-10s. **Multipart form data, not JSON** — the image goes in a `file` field.

```bash
curl -X POST http://localhost:8000/sessions/SESSION_ID_HERE/scan \
  -F "file=@/path/to/screenshot.png"
```

Response shape:
```json
{
  "flagged": true,
  "description": "A social media post referencing restricted content.",
  "warning_active": true,
  "points_awarded": false
}
```

### `POST /sessions/{session_id}/events`
Manually adds an event to a session's event log (mostly for testing — in normal flow, `/scan` adds events automatically when content is flagged).

```bash
curl -X POST http://localhost:8000/sessions/SESSION_ID_HERE/events \
  -H "Content-Type: application/json" \
  -d '{
    "content": "Test event for manual QA",
    "time_duration": 180
  }'
```
`time_duration` is optional — omit it to get a randomized 140-300s duration.

### `POST /sessions/{session_id}/flush`
Converts all pending events on a session into permanent `GuardianReport`s (visible to the owner) and clears the session's event log. Call this when the guardian views their alert inbox, or periodically.

```bash
curl -X POST http://localhost:8000/sessions/SESSION_ID_HERE/flush
```

import { createFileRoute, useNavigate } from "@tanstack/react-router";
import { useEffect, useState } from "react";
import { AppShell } from "@/components/AppShell";
import { useScanLoop, type ScanResult } from "@/hooks/useScanLoop";
import { Button } from "@/components/ui/button";
import { api, localSession } from "@/lib/api";
import { toast } from "sonner";
import { Play, Square, Sparkles, ShieldAlert, Trophy, Flame } from "lucide-react";

export const Route = createFileRoute("/guardian/monitor")({
  head: () => ({ meta: [{ title: "Session — YTG" }] }),
  component: Monitor,
});

function Monitor() {
  const nav = useNavigate();
  const [points, setPoints] = useState(0);
  const [streak, setStreak] = useState(0);
  const [pointsPop, setPointsPop] = useState(0);
  const [applauding, setApplauding] = useState(false);
  const [guardianMsgs, setGuardianMsgs] = useState({
    warning: "Please skip this one for me, okay?",
    applause: "Proud of you for moving past that ❤️",
  });

  const session = typeof window !== "undefined" ? localSession.get() : null;

  useEffect(() => {
    if (!session) nav({ to: "/auth" });
    else setPoints(session.points || 120);
  }, [session, nav]);

  useEffect(() => {
    (async () => {
      if (!session?.guardian_id) return;
      try {
        const s: any = await api.getSettings(session.guardian_id);
        setGuardianMsgs((prev) => ({
          warning: s?.custom_warning_messages?.warning || prev.warning,
          applause: s?.custom_warning_messages?.applause || prev.applause,
        }));
      } catch {}
    })();
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, []);

  function handleResult(r: ScanResult) {
    if (r.points_awarded) {
      setApplauding(true);
      setPoints((p) => p + 10);
      setStreak((s) => s + 1);
      setPointsPop((n) => n + 1);
      if (session) api.addPoints(session.user_id, 10).catch(() => {});
      setTimeout(() => setApplauding(false), 2200);
    }
  }

  const { videoRef, canvasRef, start, stop, running, state, description } = useScanLoop({
    userId: session?.user_id || "",
    guardianId: session?.guardian_id || session?.user_id || "",
    intervalMs: 5000,
    onResult: handleResult,
  });

  async function handleStart() {
    try {
      await start();
    } catch {
      toast.error("Screen share is required to start a session.");
    }
  }

  const displayState = applauding ? "applause" : state;

  return (
    <AppShell variant="individual">
      <div className="grid gap-6 md:grid-cols-3">
        <div className="rounded-2xl border border-border bg-card p-6">
          <div className="text-xs uppercase tracking-wide text-muted-foreground">Points</div>
          <div className="relative mt-2 font-display text-4xl font-semibold">
            {points.toLocaleString()}
            {pointsPop > 0 && (
              <span
                key={pointsPop}
                className="animate-points-pop absolute -right-2 top-0 text-lg font-semibold text-success"
              >
                +10
              </span>
            )}
          </div>
        </div>
        <div className="rounded-2xl border border-border bg-card p-6">
          <div className="flex items-center gap-2 text-xs uppercase tracking-wide text-muted-foreground">
            <Flame className="h-3 w-3" /> Streak
          </div>
          <div className="mt-2 font-display text-4xl font-semibold">{streak}</div>
        </div>
        <div className="rounded-2xl border border-border bg-card p-6">
          <div className="text-xs uppercase tracking-wide text-muted-foreground">Session</div>
          <div className="mt-2 flex items-center gap-2 font-medium">
            <span
              className={`inline-block h-2 w-2 rounded-full ${
                running ? "bg-success animate-soft-pulse" : "bg-muted-foreground/40"
              }`}
            />
            {running ? "Watching" : "Paused"}
          </div>
        </div>
      </div>

      <div className="mt-6 rounded-2xl border border-border bg-card p-8">
        {!running ? (
          <div className="flex flex-col items-center gap-4 py-8 text-center">
            <Sparkles className="h-8 w-8 text-primary" />
            <h2 className="font-display text-2xl">Ready when you are</h2>
            <p className="max-w-md text-sm text-muted-foreground">
              YTG will ask permission to view your screen. Every 5 seconds it takes a quiet look and
              cheers you on when you keep good habits.
            </p>
            <Button size="lg" onClick={handleStart}>
              <Play className="mr-2 h-4 w-4" /> Start session
            </Button>
          </div>
        ) : (
          <div className="flex flex-col items-center gap-4 py-6 text-center">
            {displayState === "clear" && (
              <>
                <div className="text-4xl">✨</div>
                <div className="font-display text-xl">All good. Keep going.</div>
                <p className="text-sm text-muted-foreground">Checking every 5 seconds.</p>
              </>
            )}
            {displayState === "cooldown" && (
              <>
                <div className="text-4xl">🌿</div>
                <div className="font-display text-xl">Nice — you moved on.</div>
                <p className="text-sm text-muted-foreground">Confirming a full 5 seconds…</p>
              </>
            )}
            {displayState === "applause" && (
              <div className="rounded-2xl bg-success/15 px-6 py-6">
                <Trophy className="mx-auto h-8 w-8 text-success" />
                <div className="mt-3 font-display text-2xl">+10 points</div>
                <p className="mt-1 text-sm text-success-foreground">{guardianMsgs.applause}</p>
              </div>
            )}
            {displayState === "warning" && (
              <div className="w-full rounded-2xl bg-warm/40 p-6 text-warm-foreground">
                <ShieldAlert className="mx-auto h-8 w-8" />
                <div className="mt-3 font-display text-2xl">A gentle nudge</div>
                <p className="mt-2 text-sm">{guardianMsgs.warning}</p>
                {description && (
                  <p className="mt-2 text-xs opacity-80">Detected: {description}</p>
                )}
              </div>
            )}

            <Button variant="outline" onClick={stop}>
              <Square className="mr-2 h-4 w-4" /> Stop session
            </Button>
          </div>
        )}
        <video ref={videoRef} className="hidden" muted playsInline />
        <canvas ref={canvasRef} className="hidden" />
